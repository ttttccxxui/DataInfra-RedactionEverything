## 1. 安装环境确认

### 1.1 系统定位

平台面向法律、医疗、金融、政务场景，对 Word/PDF/图片/扫描件等非结构化文件，以及 CSV/Excel/JSONL/SQLite 和数据库直连的结构化数据做本地化识别、复核与脱敏。**识别与打码所需的 OCR、语义 NER、视觉三类模型全部本地 GPU 部署，数据不出域，无外部 API 依赖。**

### 1.2 环境要求（标准基线）

| 类别 | 要求 | 说明 |
|---|---|---|
| 服务器 | 1 台 GPU 服务器（推荐 2 张 NVIDIA GPU） | 本机交付形态为单机单 worker，双卡为现行生产拓扑 |
| GPU | NVIDIA GPU，完整视觉链路推荐 ≥16 GB 显存/卡 | 双卡按「每卡一套推理实例 + 负载均衡」部署 |
| 操作系统 | Ubuntu 22.04 / 24.04 LTS | |
| GPU 驱动 / CUDA | NVIDIA 驱动，CUDA 12.8+ | 与本地 vLLM / Paddle 构建匹配 |
| 运行时 | Python 3.11（含 OCR 与 vLLM 两套虚拟环境）、Node.js 24 LTS | 由部署脚本自动创建 |
| 容器（可选） | Docker + Docker Compose（GPU 场景需 nvidia-container-toolkit） | 容器化部署走 `docker compose --profile gpu` |
| 存储 | 系统盘外独立数据盘（上传/输出/备份），建议 ≥1 TB 可用 | 平台内置磁盘水位监控与保留策略 |
| 网络 | 办公网可访问平台地址；如需 LDAP/SFTP/数据库直连，需放通对应内网端口 | 数据不出域，无需公网出口（模型离线导入） |
| 数据库 | 内置嵌入式库开箱即用，无需外部数据库 | PG/达梦适配为路线图选项 |

### 1.3 需客户方提供/确认的信息（现场逐项打勾）

| # | 确认项 | 状态 | 客户负责人 |
|---|---|---|---|
| 1 | GPU 型号、显存、卡数、当前占用情况（`nvidia-smi`） | ☐ | |
| 2 | 操作系统版本、内核、可用磁盘与挂载点 | ☐ | |
| 3 | GPU 驱动版本 / CUDA 版本 | ☐ | |
| 4 | 服务器是否可访问外网（模型下载路径：魔搭/HF/离线介质导入） | ☐ | |
| 5 | 平台访问方式：IP/域名、端口（默认前端 3000、API 8000） | ☐ | |
| 6 | 是否需要反向代理 / TLS 证书 / 统一身份（LDAP/AD） | ☐ | |
| 7 | 数据库直连需求（PostgreSQL/MySQL 地址、只读账号） | ☐ | |
| 8 | 内网文件接入方式（服务器目录导入 / SFTP 拉取 / SMB 挂载） | ☐ | |
| 9 | 防火墙放通策略与运维联系人 | ☐ | |
| 10 | 备份策略与备份存储位置 | ☐ | |

### 1.4 部署前安全基线（必须确认）

- `AUTH_ENABLED=true`；`JWT_SECRET_KEY` 使用强随机值并以 `~/.redaction_secrets`（600 权限）外置，**严禁写入脚本或仓库**；
- 仅内网访问，生产环境关闭接口文档（swagger）；
- 首次安装由第一个注册账号初始化超级管理员，其余账号由管理员创建；
- 上传/导出/数据目录纳入备份与访问控制范围。

## 2. 实施部署计划

### 2.1 总体阶段与里程碑

| 阶段 | 主要内容 | 周期（参考） | 里程碑/验收标准 |
|---|---|---|---|
| P0 环境准备 | 服务器就绪、驱动/CUDA/运行时安装、网络放通、模型权重导入 | 1–3 天（视 GPU 驱动与模型下载条件） | `nvidia-smi` 正常；两套虚拟环境可用 |
| P1 平台部署 | 后端 + 前端落位、GPU 推理服务（HaS/OCR/LocateAnything）拉起、密钥配置 | 1 天 | `curl /health/services` 返回 `all_online: true` |
| P2 冒烟与验收 | 路由冒烟、单文件/批量/库表三链路走查、四行业黄金语料复跑 | 1 天 | E2E 冒烟通过；identity 召回 100% 记分卡复验通过 |
| P3 试运行 | 客户真实样本试跑、识别项/配置清单按客户业务调优、水印与审计策略落地 | 3–5 天 | 客户确认样本结果，形成运行基线配置 |
| P4 正式上线 | 账号体系与角色开通、LDAP（如需）、备份计划生效、双账号并发验证 | 1 天 | 上线确认单签署 |
| P5 培训与交接 | 管理员/用户/运维培训、文档移交 | 见第 4 节 | 培训考核通过，交接单签署 |

### 2.2 部署拓扑（双卡生产形态）

| 服务 | 说明 | 端口（示例） |
|---|---|---|
| 前端 | 网页工作台 | 3000 |
| 后端 API | 业务、任务队列、审计 | 8000（生产实例 23001） |
| HaS Text（vLLM） | 语义 NER，每卡一实例 + 轮询负载均衡 | 29080 |
| OCR（PP-StructureV3） | 文本与字符框，每卡双实例 + 负载均衡 | 29082 |
| LocateAnything 视觉 | 人脸/印章/签字/证件等视觉特征 | 29090 / 29140 |

管理方式：`start_all.sh` 自愈式启动（只拉起 DOWN 的端口），GPU 与显存配额在启动脚本中钉死，变更需走评审。

### 2.3 升级与回滚机制（已真机演练）

- 出包：`python deploy/release.py` → 生成带版本号发行包；
- 升级：`bash deploy/upgrade.sh <包>` → 备份现网 → 应用 → 仅重启后端 → **90 秒健康门禁，失败自动回滚**；
- 升级影响面：仅应用层变更秒级重启；GPU 服务配置变更需重启对应模型服务，安排在业务低峰。

### 2.4 备份与容灾

- 数据库与配置**每小时自动热备**；
- 文件树建议每日增量备份（crontab 模板见 Runbook）；
- 恢复流程已演练（停服恢复 CLI），服务监控面板可见备份新鲜度；
- 故障自愈：重启后任务自动重排队、30s 僵死看门狗、库损坏自动恢复。

## 4. 培训计划

### 4.1 培训对象与课程

| 对象 | 课程 | 时长 | 重点内容 |
|---|---|---|---|
| **管理员** | 系统管理培训 | 半天 | 账号与五角色矩阵（管理员/审核员/普通用户/操作员/只读）、批量确认授权、审计日志检索与导出、服务监控与显存/磁盘水位、运行配置（并发数）、账号禁用、回收站、API 密钥、授权许可续期、LDAP/AD 对接说明、数据保留策略 |
| **业务用户** | 使用操作培训 | 半天 | 单次处理（上传→复核→确认→导出）、批量五步向导、键盘审阅流（←/→ 切换，Ctrl+Enter 确认）、断点续传与失败重试、库表处理（导入→字段策略→交付包）、成品水印、任务完成通知 |
| **运维人员** | 运维培训 | 半天 | 服务启动与自愈、健康检查接口、升级与自动回滚流程、备份恢复演练、常见故障处理表、密钥轮换流程、GPU 孤儿进程处理 |

### 4.2 培训方式与安排（示例）

| 场次 | 形式 | 内容 | 时长 |
|---|---|---|---|
| 第 1 场 | 集中授课 + 演示 | 平台全景 + 业务用户操作（真实样本演示） | 2 h |
| 第 2 场 | 上机实操 | 用户按课后练习在测试环境走通单次/批量/库表三链路 | 2 h |
| 第 3 场 | 管理员专场 | 角色配置、审计、监控、授权管理实操 | 2 h |
| 第 4 场 | 运维交接 | 启动脚本、升级回滚、备份恢复**实操演练** | 2 h |
| 后续 | 答疑与陪跑 | 上线后 1–2 周内定时答疑，形成常见问题库 | 按需 |

### 4.3 考核与留档

- 用户：完成一份真实样本的「识别 → 复核 → 确认 → 导出」全流程即视为通过；
- 管理员：完成一次「新建账号 + 授予批量确认 + 审计检索导出」操作；
- 运维：完成一次「模拟升级 → 健康门禁 → 自动回滚」演练；
- 培训签到表、课件、录屏（视需要）与考核记录留档并随交付物移交。

## 5. 风险提示与待办

| 风险/事项 | 影响 | 应对 |
|---|---|---|
| GPU 驱动/CUDA 版本不匹配 | 模型服务无法启动 | P0 阶段先做驱动核对，必要时统一重装 |
| 模型权重无法在线下载 | 部署延期 | 备选：魔搭下载 / 离线介质导入（需提前确认） |
| 显存不足（<16 GB 或卡被占用） | 时延上升、OOM | 关闭视觉链路或降低并发；清理孤儿进程；按白皮书调整参数 |
| 客户真实样本与合成语料分布差异 | 识别效果偏差 | P3 试运行阶段用真实样本调优识别项并固化配置清单 |
| 第三方组件商业授权（LocateAnything/PyMuPDF） | 合规风险 | 启动会明确是否商用，提前规划替代或采购 |

**启动会当场需拍板的事项**：
1. 部署形态（裸机双卡 / Docker Compose）与访问域名；
2. 是否启用 LDAP/AD、是否需要 TLS 与反向代理；
3. 培训场次时间与参训名单；
4. 上线验收标准与签字人。
